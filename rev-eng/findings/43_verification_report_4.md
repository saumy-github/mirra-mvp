## Corrections list

1. Finding 40 / FINDINGS lane AL: "else -> 0x50fda06 loop" is imprecise. 0x50fda06 is one `call 0x511a1b0` instruction inside the loop 0x50fd9e0-0x50fda1f. The "1 or 2" test is `dec eax; cmp eax,1; jbe`, with box text "Failed to load the Avatar Size file. The file was created in a lower version." at 0x83cab80 (this is a different string from the apply-step "sizing data was created in a lower version" box).
2. Lane AL, target vector: the discriminator is `0x1bf1390` = "shared_ptr is empty", so the search branch runs only when the passed current avatar is EMPTY, and the vector construction for the non-empty case is via 0x3555520 (insert one element). Wording in FINDINGS ("if a current avatar exists ... otherwise 0x50ccdc0") is correct.
3. Lane AL validation: it breaks at the first failing target (jne inside the loop), not after testing all. Same outcome.
4. Lane AF: state the bound precisely: compare is `cmp count,group; jb fail`, i.e. rejects `group > count` only; `group == count` passes and indexes past the end of the 16-byte-entry vector at manager+0x200..0x208.
5. Lane AJ: the caveat "accepts zfab, jfab, xtex, axf, sbsar, gltf, glb" is inside 0x5cdcca0 and was not re-verified here; the return-value claim is verified.
6. Lane AB: no corrections.
7. Lane AK: the gating applies to the whole-scene path (0x5d6eed0 -> 0x5cabc90); the copied internal option object, not the caller's, is what 0x5cabc90 tests (the copy preserves +8/+9).
