## 2. Mismatches

1. **CSV bridge format is wrong (blocker for the csv route) [V by finding 15 vs step_06 `_build_csv_bridge`].** The pipeline writes a wide 2-row CSV (headers `Total Height,Weight,Chest,...`, one value row). CLO's parser wants line 1 ignored, line 2 `Something(cm)`, then rows `Name,Type,Value`. The wide file yields "Avatar size needs total height." Also the headers use pipeline names (`Chest`, `Low Hip` with no `_Type`). Correct keys: `Total Height,Height`; `Bust,Circumference`; `Waist,Circumference`; `Low Hip,Circumference`; `Inseam,Height`; `Across Shoulder (Curvilinear),Length`. The csv route is legacy (needs `--enable-legacy-route`) so impact is limited to that route.
2. **Name mismatch "Chest" vs "Bust".** idx 2 is the key `Bust_Circumference`; the contract calls it Chest. Harmless for index routes, fatal for CSV/property routes if the literal is used. `Weight` has no CLO key at all (csv route would silently ignore it; avs/avt skip it).
3. **Half vs full circumference: no mismatch.** Mirra stores full circumference in cm and CLO keys are full circumference in cm [V]. Only risk: if user-entered values are ever half-girths, nothing converts them. Range checks in step_03 (chest 50-180, waist 40-220, hip 50-220) assume full girth.
4. **Semantic mismatches (value goes to a different quantity).** `leg_length_cm` -> Inseam Height (idx 26): inseam height is floor-to-crotch, close to but not leg length (outer leg 40-140 sanity range is far wider than inseam). `shoulder_width_cm` (range 20-80, likely straight point-to-point) -> Across Shoulder (Curvilinear), a surface arc: template value 44.13, expect straight width of 40-46 to be a few cm short [I]. `hip_circumference_cm` -> Low Hip (idx 8) rather than High Hip idx 7 or widest-hip: acceptable [I].
5. **Indices are correct for the 6 mapped fields [V]** (0, 2, 6, 8, 26, 36 agree with finding 15 table and finding 13 map; ridge `input_indexes` identical). No wrong indices found. But `avs_patch.FEATURE_COUNT = 57` while the .avs holds 62 floats (finding 13) and CLO's float[67]; the tail (idx 57-61: Vertical Trunk, Hand, Head Circ, 60-61) is not touched. Fine for the driven six, but ridge/derived only covers idx <= 56 [V]. Idx 57-59 are in CLO's key table (Vertical Trunk, Hand, Head) so they can be set; Mirra does not.
6. **Derived values: setting a measure CLO would derive has an effect?** In CLO's CSV importer every non-zero CSV value is set with mode 2 (or i+4 for typed features) and then a two-stage solve re-derives dependents [V finding 15 sec 1.3]. So Waist, Low Hip, Inseam, Across Shoulder are real constraints, not ignored. Only Total Height (mode 3) and Bust (mode 1) are the true drivers; the other four override what CLO would derive from height+bust. Weight (idx 1) cannot be set by CSV, so sending it does nothing there [V]. On the avs/avt routes there is no solve at all (floats written verbatim, `listMeasureMode` kept from template), so mesh response depends on the template modes (findings 10/13: avt_patch does not re-deform the mesh; avs does).
7. **Required drivers.** Male: Total Height + Bust(=chest) both present and validated by `get_v1_fields_for_gender` in step_03 [V]. Female: nothing implemented (needs Under Bust idx 5 mode 1; step_03 raises for non-male).
8. **Derived values are model guesses.** On the avs route 51 floats come from a ridge regression trained on 25 samples (LOO RMSE median 0.67 cm, max 4.19), valid only for chest 86-132 cm, waist 72-123 cm (training note) [V]. Inputs outside this are extrapolations; step_03 ranges (chest 50-180) are much wider than the model's validity.

## 3. CLO supports, Mirra does not collect

From the key table (finding 15): Neck Base, Mid Thigh/Thigh/Knee/Calf/Ankle circumferences, Bicep/Elbow/Wrist, High Hip, Head; heights Waist/High Hip/Low Hip/Thigh/Knee/Calf; HPS height; lengths Shoulder Drop, Across Front/Back, CF/CB Neck to Waist, Waist to High/Low Hip, Apex to Apex, HPS to Apex, Arm length, Total/Front/Back Rise, Vertical Trunk, Hand. Most relevant for garment fit: **Arm Length (idx 47)**, **Neck Base (4)**, **Bicep (15)**, **Thigh (9)**, **Across Back/Front (35/34)**, **CB Neck to Waist (41)**, **Underbust for female (5)**. Mirra collects none of these (garment Step 2 has sleeve_length_cm and bicep_width_cm, so body-side Arm and Bicep would be the natural pairing).

## 4. Recommended minimal driver set

Minimal valid CLO input: `Total Height` (idx 0, mode 3) + `Bust` (idx 2 male, or `Under Bust` idx 5 female, mode 1). Everything else is derived by CLO (csv route, two-stage solve) [V finding 15]. Recommended for Mirra (all cm, full circumference): required `Total Height`, `Bust`; optional high-value overrides `Waist` (6), `Low Hip` (8); then add `Arm` (47) and `Inseam` (26) only if measured accurately. Treat `Across Shoulder (Curvilinear)` (36) as optional until the Mirra shoulder measure is defined as the over-the-shoulder arc, and drop `Weight` from the driver list (no CLO key; weight cannot be applied except as a derived idx 1 float). For the avs route keep the current six-float write (indices verified), but widen the ridge training range before accepting users outside chest 86-132 / waist 72-123.
